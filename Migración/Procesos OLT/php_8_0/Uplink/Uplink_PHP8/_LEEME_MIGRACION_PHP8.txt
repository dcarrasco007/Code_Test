------------------------------------------------------------------------

2. Rutas absolutas de producción (include, nohup, exec) se dejaron

QUÉ ROMPÍA EN PHP 8.0 Y CÓMO SE RESOLVIÓ (resumen global)
------------------------------------------------------------------------
A) eregi_replace()  [ERROR FATAL en PHP 8]
   - Función POSIX eliminada en PHP 7.0.
   - Uso original:  @eregi_replace("[\n|\r|\n\r]", '', $linea)
   - Reemplazo:     preg_replace('/[\n|\r|\n\r]/', '', $linea)
   - La clase de caracteres es idéntica (elimina \n, \r y el carácter '|'),
     por lo que el resultado es EXACTAMENTE el mismo. El patrón original no
     tenía letras, así que la insensibilidad a mayúsculas de "eregi" era
     irrelevante. Se quitó el "@" porque preg_replace no emite el aviso que
     sí generaba la función antigua.

B) Constantes "bareword" sin comillas  [ERROR FATAL en PHP 8]
   - USER, PASSWORD, SALTO, SHELL, SHELL_CONFIG, SHELL_CONFIG1, SHELL2,
     SALIR, ESPACIO, ESPACIO2.
   - En PHP 5.3 una constante no definida se evaluaba como su propio nombre
     en texto (con un E_NOTICE). En PHP 8.0 eso lanza "Error: Undefined
     constant". Estas se usan como etiquetas de los switch de
     expect_expectl() y como valor de retorno de cada patrón.
   - Solución: al inicio de cada archivo que usa telnet se agregó un bloque
     que las define con su propio nombre como valor, SOLO si no existen ya:
        foreach ([...] as $__const) {
            if (!defined($__const)) { define($__const, $__const); }
        }
   - Esto reproduce EXACTAMENTE el comportamiento de PHP 5.3. Si el include
     conexion_db.php ya las definiera, el "if (!defined())" evita
     redefinirlas, así que es seguro en cualquier caso.

C) Variables usadas sin inicializar ($b, $ERROR, $ERROR2)  [Warning en PHP 8]
   - No es fatal, pero PHP 8 escala estos avisos y llenarían los .log de los
     procesos nohup. Se inicializan a 0 al comienzo de su ámbito. El valor
     null previo también valía 0 en las comparaciones y en ++, por lo que la
     lógica es idéntica.

D) Extensión "expect" ausente en PHP 8  [ERROR FATAL en PHP 8]
   - expect_popen()/expect_expectl() venían de la extensión PECL "expect",
     que NO soporta PHP 8 (ver más abajo). Sin ella el telnet fallaba con
     "Call to undefined function expect_popen()".
   - Solución: se creó expect_compat.php, una capa en PHP puro que reimplementa
     esas funciones y sus constantes hablando Telnet por socket (fsockopen).
     Se incluye con require_once en los 4 procesos de telnet y se cambiaron
     mecánicamente fwrite($stream,...) -> expect_send($stream,...) e
     ini_set("expect.timeout",n) -> expect_set_timeout(n). La lógica de
     estado_equipo* no cambió. Ver la sección "CAPA DE COMPATIBILIDAD".

------------------------------------------------------------------------
- Extensión PECL "expect" compilada/instalada para PHP 8.0 (provee
  expect_popen, expect_expectl y las constantes EXP_EXACT, EXP_REGEXP,
  EXP_TIMEOUT, EXP_EOF). Es un requisito de infraestructura, no de código.
- Extensión mysqli habilitada.
- Comandos del sistema disponibles: telnet, ping, nohup, php (CLI).

NOTA sobre mysqli y versiones futuras:
  En PHP 8.0 el modo de error de mysqli por defecto es SILENCIOSO
  (MYSQLI_REPORT_OFF), por lo que "->query(...) or die(...)" funciona igual
  que en 5.3. A partir de PHP 8.1 el valor por defecto pasa a lanzar
  EXCEPCIONES; si algún día suben a 8.1+ habría que agregar al inicio:
        mysqli_report(MYSQLI_REPORT_OFF);
  para conservar este patrón. (No se agregó porque el objetivo es 8.0.)

CAPA DE COMPATIBILIDAD  expect_compat.php  (reemplazo de la extensión expect)
------------------------------------------------------------------------
Archivo: Uplink_PHP8/expect_compat.php
Por qué: la extensión PECL "expect" no soporta PHP 8. Este archivo la
reemplaza en PHP puro, sin extensiones ni binarios externos.

Qué provee (misma semántica que usaba el código):
  - expect_popen("telnet <ip>")  -> abre la sesión Telnet por socket.
  - expect_expectl($s, [...], $m) -> espera patrones (EXACT/REGEXP), maneja
    la negociación Telnet (IAC), acumula la salida y devuelve el valor del
    patrón que coincide, o EXP_TIMEOUT cuando el equipo deja de responder.
  - expect_send($s, "texto\n")   -> reemplaza a fwrite($stream, ...).
  - expect_set_timeout(n)         -> reemplaza a ini_set("expect.timeout", n).
  - Constantes EXP_EXACT, EXP_REGEXP, EXP_TIMEOUT, EXP_EOF, etc.

Cómo se integró (cambios mecánicos en los 4 procesos con telnet):
  - require_once del expect_compat.php al inicio.
  - fwrite($stream, ...)          -> expect_send($stream, ...)
  - ini_set("expect.timeout", n)  -> expect_set_timeout(n)
  La lógica de los switch/case de estado_equipo* NO cambió.

Parámetros ajustables (constantes al inicio de expect_compat.php), por si
al probar contra una OLT real hiciera falta afinar:
  - EXPECT_COMPAT_EOL             (fin de línea enviado; por defecto "\r\n")
  - EXPECT_COMPAT_CONNECT_TIMEOUT (segundos para conectar el socket)
  - EXPECT_COMPAT_DEFAULT_TIMEOUT (silencio del equipo -> EXP_TIMEOUT)
  Los timeouts por función se respetan vía expect_set_timeout(2)/(30), que
  quedan igual que los ini_set("expect.timeout", ...) originales.

IMPORTANTE - PROBAR CONTRA UNA OLT REAL:
  El shim se validó con 17 pruebas unitarias (coincidencia de patrones,
  consumo de buffer, parser Telnet IAC) y con una prueba end-to-end contra
  un servidor que simula el diálogo Huawei (login -> enable -> config ->
  display port traffic -> logout): capturó el tráfico correctamente.
  Aun así, cada modelo/firmware de OLT puede variar el prompt o los tiempos;
  ejecuta primero UN proceso a mano contra una OLT y revisa el .log antes de
  reactivar todos los cron. Si algo no calza, ajusta los parámetros de
  arriba (normalmente EXPECT_COMPAT_EOL o los timeouts).
